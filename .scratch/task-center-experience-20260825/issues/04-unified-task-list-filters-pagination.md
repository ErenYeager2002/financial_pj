# 04 建立统一分页列表、计数与筛选

Status: ready-for-human
Category: enhancement
Priority: P1
Blocked by: 01, 02, 03

## Agent Brief

**Category:** enhancement
**Summary:** “我的任务”使用一份统一分页列表展示所有正式任务类型并提供一致筛选。

**Current behavior:**
页面先铺开应收核销批次和单日执行，再显示独立分页的普通任务。唯一状态筛选只作用于普通任务，用户选择失败后仍会看到未筛选的应收核销记录。页面没有统一类型、Skill、业务日期或更新时间筛选，也没有跨类型状态计数。

**Desired behavior:**
页面顶部显示待处理、执行中、失败和已完成数量；下方使用一份任务中心条目列表，通过类型标签区分普通任务、应收核销日期执行和批次。所有筛选和分页作用于整份列表，URL 查询参数可刷新、分享和前后导航。已取消可筛选但无需占用顶部主计数卡。

**Key interfaces:**
- `TaskCenterPage` — 页面唯一的正式任务列表数据源
- URL 查询参数 — 页码、视图状态、类型、Skill、业务日期范围和更新时间范围
- 任务中心列表项 — 复用应收核销可辨识性规则，并为普通任务提供相同的信息层级
- 筛选空态 — 区分账号没有任何任务与当前条件没有匹配项

**Acceptance criteria:**
- [x] 三种正式任务类型按最近更新时间出现在同一分页列表中
- [x] 顶部显示待处理、执行中、失败、已完成四个计数，失败与待处理具有明确视觉优先级
- [x] 状态、类型、Skill、业务日期和更新时间筛选作用于全部条目，而不是单一区域
- [x] 筛选与页码保存在 URL；修改筛选时回到第一页，翻页保留全部筛选条件
- [x] 有任务但当前筛选无结果时显示“当前筛选没有匹配任务”和清除筛选操作
- [x] 账号从未创建正式任务时才显示创建任务引导
- [x] 每项无需进入详情即可看到类型、业务日期、中文状态、进度、更新时间和下一步操作
- [x] 前端数据层、筛选序列化、分页和空态测试通过

**Out of scope:**
- 任务提醒的显示与手动补查交互
- 详情页失败指引
- 无限滚动或客户端一次加载全部历史记录
