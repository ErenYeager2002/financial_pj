# 05 统一批次失败状态和下一步指引

Status: ready-for-human
Category: bug
Priority: P1
Blocked by: 01

## Agent Brief

**Category:** bug
**Summary:** 批次失败后明确失败位置、后续停止状态和当前允许操作，不再显示冲突指引。

**Current behavior:**
批次已经失败时，页面仍可能根据子执行状态显示“当前执行”；用户手动查看失败日期时会同时看到“当前查看”和另一日期“当前执行”。失败摘要在可重试时仍可能要求联系管理员，页面没有统一说明后续日期是否停止以及重试会影响哪些日期。

**Desired behavior:**
终态批次不再存在“当前执行”概念。失败区明确回答失败日期和步骤、后续日期已经停止或尚未开始、当前用户可以执行的下一步。允许安全重试时说明只从失败日期继续且已成功日期不重复；不允许重试时显示具体阻止原因和需要联系的角色。详情始终使用后端授权和安全策略作为操作依据。

**Key interfaces:**
- 批次当前执行选择函数 — 只有非终态批次才能返回当前执行日期
- `WorkflowBatchRead` 的重试表示 — 区分技术可重试、当前用户可执行和不可重试原因
- 批次失败摘要 — 提供失败日期、失败步骤、后续日期状态和下一步说明
- 重试操作 — 保持既有只允许安全阶段重试的限制

**Acceptance criteria:**
- [x] 批次为失败、已取消或已完成时，任何日期都不显示“当前执行”
- [x] 失败批次默认定位失败日期，并显示失败步骤或安全的通用失败位置
- [x] 页面明确说明后续日期已经暂停或未开始，不把它们显示为处理中
- [x] 出现重试按钮时不再同时显示泛化的“联系管理员”指引
- [x] 可重试说明明确已成功日期不会重复；不可重试说明展示具体原因和应联系的角色
- [x] 失败、可重试、不可重试、取消和终态陈旧子状态均有回归测试

**Out of scope:**
- 扩大允许自动重试的步骤范围
- 修改多日期严格串行和失败后停止规则
- 展示原始异常、路径、URL 或堆栈
