# 应收核销回款类型判定规则修订

Status: ready-for-human

日期：2026-08-30

## 目标

补充父回款金额与关联 SO 交付额不一致时的分支规则，明确整笔回款和分笔回款的不同处理方式，避免把正常分笔回款误判为挂账。

## 边界

- 本轮已按用户确认修改代码、Skill、平台副本和回归测试；没有执行真实核销或财务工作簿写入。
- 保留现有的重复核销、金额口径、币种、关联订单完整性和写前校验规则。

## 验收方向

- 整笔回款按订单已核销金额合计作为首选口径，全部缺失时才用完整交付额合计兜底；父金额高于选定订单金额合计时，各 SO 仍按选定金额处理，超出部分记为父回款未分配余额。
- 整笔回款父金额低于选定订单金额合计超过 1 元时，整笔及关联 SO 挂账人工核查。
- 分笔回款按逐 SO 核销明细或交付额顺序分配；父金额高于逐 SO 核销合计或全部交付额合计时允许处理，超出部分不分摊进订单。
- 缺少回款类型、订单关联不完整或金额口径不可比时，继续挂账，不猜测。

## 本轮实施

- 2026-08-31：父额校验改为只拦截“父额低于订单金额合计超过 1 元”；整笔和分笔的父额超出部分写入 `unallocated_parent_amount` 或顺序分配审计，不进入 SO/SOD 金额。
- 源 Skill 测试 466 passed、5 skipped；开发端 Skill 版本为 1.6.12，API 注册表无错误。
- 2026-09-02：父回款优先使用智云“总到账金额”，不从中扣减手续费、税费或其他费用；整笔回款父 AR 审计不套用订单汇率。智云已有明确原币总到账且订单原币金额完整、订单币种一致时，直接比较原始数值合计。
