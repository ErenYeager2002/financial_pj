# 应收核销任务易用性与串行执行规格

状态：已完成并部署

日期：2026-08-20

## 目标

减少文件中心、日期选择和任务列表中的重复信息，并确保 `ar-hexiao-daily` 在任意时刻只运行一个业务任务。

## 业务规则

1. 文件中心默认只展示当前可使用的输入材料，以及每个逻辑结果的最新文件。旧文件保留在存储和审计关系中，但不在文件中心重复出现。
2. 核销日期支持单击切换选中状态，也支持按住日期后滑动批量选择；滑动选择完成后仍可单击任意日期取消。未来日期不可选。
3. `ar-hexiao-daily` 使用平台级单任务互斥。`queued`、`running`、等待人工检查和等待确认均视为进行中；只有成功、失败或取消后才能创建下一任务。多日期批次整体视为一个任务。
4. UUID 继续作为数据库主键和路由参数。页面增加持久化业务任务号，格式为 `<skill-id>_<M>.<D>_<当日序号>`，例如 `ar-hexiao-daily_8.20_1`。序号按 Asia/Shanghai 的任务创建日期、Skill 全局递增。

## 验收

- 同一逻辑结果重复生成后，文件中心只返回最新记录，旧记录仍可通过原任务审计访问。
- 长按滑动经过多个可选日期时，这些日期全部选中；随后单击其中一天可取消。
- 任一未结束的应收核销单日任务或批次存在时，再启动任务返回 409，并说明当前业务任务号。
- 单日和多日期子任务都具有稳定业务任务号；页面不再把 UUID 当作任务名称展示。
- 数据迁移后历史任务也具有不重复的业务任务号。

## 验收结果

- 文件中心使用 `latest_only` 服务端查询：输出按 Skill 与文件名保留最新记录；输入只展示当前业务材料版本引用的文件，旧记录仍保留在任务和审计关系中。
- 日期选择统一使用 Pointer Events；长按 320 ms 后滑动加入日期，普通单击可切换单日，未来日期不可选。
- 创建、失败任务重置和失败批次重试共用数据库锁与平台级单任务检查；相关 API 回归测试通过。
- 工作流及批次均保存业务任务号；历史数据迁移后空值和重复值均为 0，UUID 仅用于内部路由。
- 后端全量测试、Ruff、前端 45 项测试、TypeScript、契约检查、Lint 与 Next.js 生产构建通过。
- 已部署至 `https://localhost:8443`，Alembic revision 为 `8e31b7c4d2a9`。
