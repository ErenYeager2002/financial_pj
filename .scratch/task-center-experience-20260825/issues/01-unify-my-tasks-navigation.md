# 01 统一“我的任务”导航来源

Status: ready-for-human
Category: bug
Priority: P0
Blocked by:

## Agent Brief

**Category:** bug
**Summary:** 普通用户只通过“我的任务”访问任务列表，所有任务详情返回同一来源。

**Current behavior:**
生产导航同时提供“我的任务”和“后台任务”。应收核销单日执行与批次详情把“后台任务”作为面包屑父级，详情中的返回操作也进入单独的工作流创建/列表页面。现有导航和面包屑测试把这两个同级入口作为预期行为。

**Desired behavior:**
“我的任务”是普通用户唯一的任务列表入口。工作流路由可以继续承担创建应收核销任务和承载详情的内部职责，但不再作为同级生产导航项，也不使用“后台任务”作为用户可见概念。单日执行、批次和普通任务详情均以“我的任务”为列表来源；直接打开创建页时使用“创建任务”或具体 Skill 的创建语义。

**Key interfaces:**
- `getPlatformNavigation()` — 员工和管理员生产导航不再返回“后台任务”同级项
- `getPlatformRouteTitle()` 与面包屑构建接口 — 工作流详情的父级显示“我的任务”并链接统一任务列表
- 工作流单日和批次详情的返回操作 — 返回统一任务列表；批次子执行仍先返回所属批次
- 工作流创建入口 — 仍能从 Skill 中心、任务提醒和直接链接到达，不依赖侧栏入口

**Acceptance criteria:**
- [x] 财务员工和管理员侧栏、命令面板都只出现一个任务列表入口“我的任务”
- [x] 应收核销单日详情和批次详情的面包屑父级均为“我的任务”并链接统一列表
- [x] 详情页“返回任务列表”进入统一列表；批次子执行的“返回所属批次”保持不变
- [x] 从任务提醒进入创建页仍会预选 Skill 和全部可处理日期
- [x] 创建页不再以“后台任务”作为页面标题或用户可见类别
- [x] 导航、面包屑和任务提醒跳转测试覆盖上述路径

**Out of scope:**
- 改变工作流详情和创建路由的内部 URL
- 合并普通任务与工作流的数据库状态机
- 修改应收核销执行或重试规则
