# 财务 Skill 平台完善规格

日期：2026-08-15

实施状态：P3-01 至 P3-05 已完成并部署，验收证据见 `docs/PLATFORM_COMPLETION_DEPLOYMENT_2026-08-15.md`。

## 目标

在保留现有身份、平台角色、Skill 权限、文件哈希、审批、审计和确定性执行边界的前提下，把当前功能集合整理成员工能够理解、管理员能够治理、任务过程能够追踪的完整财务 Skill 平台。

参考调研见 `docs/GITHUB_OPEN_SOURCE_REFERENCE_RESEARCH_2026-08-15.md`。

## 用户路径

员工从工作台、Skill 中心或 AI 助手发起需求，最终都进入统一任务路径：

`选择或识别 Skill → 绑定平台文件和参数 → 自动预检 → 用户确认 → 执行 → 必要时审批 → 受控写入与复核 → 下载结果`

管理员通过待办和 Skill 治理处理审批、发布审核、权限和审计，不在 Skill 业务详情中混入治理操作。

## 不变量

- Clerk 只证明登录身份，菜单和业务权限使用平台本地角色。
- `finance_user` 不能看到或调用管理员页面；页面隐藏不能替代后端鉴权。
- AI 只能生成任务草稿、补充参数和解释结果，不能直接执行、审批或写文件。
- 写入审批绑定固定 Skill 版本、参数、平台文件及 SHA-256、预览和有效期。
- 失败重试只能重试明确可幂等的步骤，不默认重跑整个写入任务。
- 普通员工不能通过网页创建任意代码、Shell、数据库写入或 unrestricted HTTP 节点。

## 产品结构

生产导航分为四组：

1. 我的工作：工作台、Skill 中心、我的任务、文件中心、AI 助手。
2. 待办：待我审批。后续任务确认聚合完成后加入待我确认。
3. 管理：Skill 治理、组织与成员。
4. 账号：个人资料、消息通知。

模板中的产品管理、看板、在线沟通、账单、表单、图标、专属功能和数据查询示例不得出现在生产导航和命令面板。现阶段只隐藏入口，不批量删除源文件。

## 步骤级执行模型

- `WorkflowDefinition`：受控工作流的稳定标识、版本、状态和所属 Skill。
- `StepDefinition`：步骤类型、顺序、输入输出约束、超时、重试、风险和 Worker 路由。
- `StepRun`：一次任务中某一步的状态、尝试次数、时间、输入输出摘要和错误。
- `ArtifactBinding`：步骤与输入输出平台文件及哈希的不可变关联。
- `ApprovalBinding`：审批记录与具体步骤及执行快照的关联。

首批步骤类型固定为参数校验、文件校验、只读 HTTP、Python、RPA、结果预览、人工确认、管理员审批、受控写入、写后复核和产物归档。

## 验收

- 两种平台角色得到不同的生产导航，命令面板与侧栏一致。
- 所有管理员页面继续执行服务端平台角色校验。
- 任务详情能显示步骤状态、任务事件、输入输出文件、审批和失败原因。
- 模型不可用时仍能从 Skill 中心手工创建任务。
- 新增数据库结构有迁移、模型测试、资源隔离测试和兼容旧任务的测试。
- 前端通过导航结构测试、TypeScript、lint 和生产构建；后端通过定向测试、全量测试和 Ruff。

## 发布边界

每张任务票独立验证，不在同一次改动中删除模板模块、替换认证系统或引入新的大型编排运行时。P3-01 至 P3-04 在本地验证后再统一重建容器和部署。
