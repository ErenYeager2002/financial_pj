# 文件中心自动保留

每个用户、部门、工具分别保留最后一次成功运行的输入和输出。多日期批次按整批成功处理；失败、执行中、等待补充材料的任务不会替换上次成功文件。新上传尚未使用的文件、未提交草稿、正在使用的输入和财务材料版本继续保留。历史材料版本仍由原有文件中心可见性规则隐藏；原始取数、工作副本、恢复目录不属于此清理范围。

持久化入口为 deployment/retain_files.py，默认只读，--apply 执行。主机用户 cron 每分钟在平台正常且部署锁可用时运行；通过当前健康 API 容器的独立 Python 进程加载持久化源码，不重启 API、Worker 或前端。--install-guard 为在线数据库保护迁移，只在安装或明确升级时执行。

完整性哈希在任务调度锁外计算，删除前重新核对任务和文件元数据。数据库共享引用锁、删除触发器和退休凭据保护草稿输入、任务引用与存储路径，兼容仍在运行的旧输出清理器。旧任务的文件已被成功运行替换后，不能直接以已清理的输入恢复执行，需使用当前文件。清理只记录元数据审计，不保留被删除文件的额外副本。

回滚：用 crontab -e 仅删除 # financial-platform-file-retention-v1 标记及其下一条任务；现有服务无需重启。已执行的文件删除不因停用定时任务 恢复。保留 file_retention_receipts 与保护触发器，防止重新引用已清理的 ID；不要直接删除该表。修改 SQL 时先在隔离 PostgreSQL 中验证，再经 --install-guard 事务更新。

验证采用当前 API 镜像中的隔离 SQLite 文件策略测试和无生产卷、无对外端口的独立 PostgreSQL 并发测试，不执行真实财务任务。

安装入口为 deployment/install_file_retention_cron.py，保留已有 crontab。当前主机 cron 已运行，按用户当前组权限启动；不修改 Docker socket 权限或重启用户服务。日志标记为 financial-platform-file-retention。
