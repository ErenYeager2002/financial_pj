# ADR 0003：应收核销保留 Workflow 与 Pi Harness 两种执行方式

- 状态：Accepted
- 日期：2026-09-03

## 背景

应收核销已有稳定的 Workflow Worker，但业务希望同一入口也能由 Pi Harness 按 Skill 要求全程执行。页面中的日期、材料、取数来源、任务进度和结果下载继续复用现有实现。

## 决策

每个任务创建时固定 `execution_mode`，取值为 `workflow` 或 `pi_harness`，执行中不切换，也不自动回退。

平台通过 `ReconciliationRunner` 选择执行器。Workflow 适配器继续串联原有动作；Pi Harness 适配器只创建 Agent 调度动作。独立 Agent Worker 领取动作后，读取该任务固定 Skill 快照中的完整 `SKILL.md` 和 `config/agent-tools.yaml`，并获得当前任务保存的完整业务上下文、输入材料元数据、产物、消息、动作输入输出和批次状态，再逐步请求 Python Workflow Worker 执行受控工具。逐笔 AR、订单、核销和异常明细通过受控分页工具读取；任务目录内的 JSON、CSV、Markdown、YAML 和文本资料也可以分页读取。任务上下文中的工作区路径和业务汇总可以提供给模型；业务凭据、内部令牌、模型密钥和会话认证信息在进入模型前统一过滤。

Pi Harness 与 FastAPI 使用独立内部令牌认证。模型请求仍经过平台模型网关，模型密钥只在 FastAPI 中解密。一个任务只能有一个活动的 Pi Harness 租约。

写入工具在排队前核验四项内容：任务固定的核销日期、当前材料版本、校验后计划指纹和任务所属账号的 Skill 权限。写入动作继续使用暂存副本，并在发布前后执行回读校验。写入失败和 Agent 租约中断均不自动重试。

多日期批次仍由平台按日期升序创建单日任务。每个单日任务沿用批次固定的执行方式；前一天完成并发布新的材料版本后，下一天才能开始。

## 结果

前端仅增加执行方式选择，其余任务展示和结果结构不变。两种执行方式共用同一套任务、材料、取数包、审计和产出模型，因此不会形成两套业务数据。
