## Root producer eligibility clarification after the first actual red

To preserve an original pre-registration gate error without a second database failure masking it, the original ArExecution instance may retain a bounded invocation-local set of record IDs whose prepared commit returned successfully. Populate it only after the actual prepared+Audit commit acknowledgement, before the second launch fence. The terminal callback skips a record never confirmed committed; it must still validate original bridge/binding afresh before any eligible terminal append. Thus a second-fence/Popen denial after confirmed prepared commit retains launch_unconfirmed, while before-commit failure invents no ref and preserves its original cause. A lost prepared-commit acknowledgement deliberately leaves terminal absence unknown even if the prepared commit actually succeeded; this marker is not no-launch/no-effect proof or authority. The narrow registrar still validates original identity, immutable duplicate/conflict and late observations. Its caller isolation and actual cleanup-first policy remain. The frozen anchor/persisted8-field prepared contract is not repurposed as an eligibility flag.
