# PR-04 补取申请实际操作者与原子审计

## 问题和实现

单日/批次补取服务此前没有实际 actor 参数，也没有锁后刷新目标。服务先提交补取动作，HTTP 再追加审计；审计失败仍留下可执行动作。新增真实数据库路由函数用例复现6项失败：两条路径的旧管理员身份、陈旧阶段及审计失败部分提交。

backend/app/workflow_service.py 两个公开补取服务现在要求显式 actor，在 scheduler 锁后刷新目标、当前身份/部门/归属/Skill权限，并独立检查 owner。批次同时刷新子任务及动作关系，保留材料版本、日期归属和选中子任务的独立授权。私有 _prepare_fetched_data_supplement 只准备状态、动作和消息，不提交；仅两条已授权公开路径调用。公开用例追加原事件名称及数量摘要，使用当前实际actor，与准备结果同事务提交。

backend/app/main.py 两个路由传递请求用户，移除服务提交之后的重复审计和提交。对外请求、响应和审计事件名称保持；未增加模型能力或真实补取。

## 验证

14项新数据库路由用例覆盖身份、阶段、正向owner/admin、快照拒绝及审计故障回滚，业务鉴权/排队真实执行，仅响应序列化用替身。补取动作不会被测试Worker领取。既有快照业务单元测试改测私有准备函数，公开快照限制由新用例覆盖。最终180项专项通过，静态diff与双轴审查通过。

候选/恢复镜像的隔离PG迁移、重复迁移、只读角色、事务与恢复模式检查通过。新业务审计仅包含AR/SO数量，不包含业务单号。
