# 02 让应收核销任务在列表中可辨识

Status: ready-for-human
Category: enhancement
Priority: P0
Blocked by:

## Agent Brief

**Category:** enhancement
**Summary:** 应收核销列表行无需进入详情即可区分日期、状态、进度和失败原因。

**Current behavior:**
多日期批次使用相同的“应收核销日清 · 多日期批次”标题，单日执行只附带一个日期；状态直接显示内部英文值。列表没有展示日期范围、更新时间、进度消息、失败摘要或业务任务号的清晰层级。

**Desired behavior:**
当前任务中心的应收核销区域先获得可复用的任务行/卡片表现。批次以起止业务日期和日期数为主标识，单日执行以业务日期为主标识；状态使用统一中文视图，显示进度、更新时间和安全失败摘要。业务任务号作为次要信息，不用 UUID 或“多日期批次”充当名称。

**Key interfaces:**
- `WorkflowRead` 与 `WorkflowBatchRead` 列表表示 — 使用已有业务日期、业务任务号、进度、错误、创建和更新时间字段
- 工作流状态展示函数 — 为单日执行和批次提供一致的中文状态与视觉变体
- 应收核销任务列表项 — 同时支持单日和日期范围，不暴露敏感错误详情

**Acceptance criteria:**
- [x] 批次列表项显示起止业务日期和日期总数；单日执行显示唯一业务日期
- [x] `queued`、`running`、`waiting_confirmation`、`failed`、`succeeded`、`cancelled` 等内部状态均显示中文
- [x] 每项显示百分比进度、当前进度说明和最近更新时间
- [x] 失败项显示经过现有脱敏策略处理的短摘要，非失败项不占用失败信息空间
- [x] 业务任务号显示在次要信息中，列表不显示 UUID
- [x] 不同日期范围、中文状态、失败摘要和更新时间具有前端回归测试

**Out of scope:**
- 跨普通任务、单日执行和批次的统一分页
- 新增搜索或筛选条件
- 改变详情页状态机或重试能力
