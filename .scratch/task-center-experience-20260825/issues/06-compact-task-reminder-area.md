# 06 降低空提醒区的视觉优先级

Status: ready-for-human
Category: enhancement
Priority: P1
Blocked by:

## Agent Brief

**Category:** enhancement
**Summary:** 任务提醒只在有待办或失败时突出显示，手动补查成为次要操作。

**Current behavior:**
任务中心始终先显示完整任务提醒卡片和补查日期表单，即使没有提醒或检查失败。低频补查操作占据首屏；组件异步错误只以红色文字显示，没有告警语义。

**Desired behavior:**
有待处理日期时显示提醒区，并直接提供“处理这些日期”；有检查失败时显示安全失败摘要和重试。完全空闲时隐藏提醒主体或缩成一行状态，手动补查放入次要操作、折叠区或对话框。异步错误可以被辅助技术及时识别。

**Key interfaces:**
- `TaskReminderBoard` — 根据提醒和终态检查失败区分待办、异常和完全空闲三种展示状态
- 手动补查操作 — 保留最近 31 天限制，但不作为空页面的主操作
- 提醒错误反馈 — 使用可访问告警和 `aria-live`，仍显示脱敏错误
- 多日期处理链接 — 继续排除已经关联正式任务的日期

**Acceptance criteria:**
- [x] 有待办提醒时显示日期、数量和“处理这些日期”主操作
- [x] 只有检查失败时显示失败提示和重试，不显示空待办卡片
- [x] 没有提醒和失败时不占用完整首屏卡片，手动补查仍可通过次要操作到达
- [x] 手动补查继续限制为最近 31 天，失败不会清除用户选择的日期
- [x] 异步失败容器具有 `role="alert"` 或等效可访问语义
- [x] 空闲、待办、检查失败和手动补查四种状态具有前端测试

**Out of scope:**
- 改变 09:10 调度、自动重试和负责人权限
- 把任务提醒当成已经创建的正式任务
- 自动启动应收核销
