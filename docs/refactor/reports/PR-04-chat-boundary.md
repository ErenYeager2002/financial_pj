# PR-04 聊天模型决策前后边界

## 问题与改动

send_workflow_message 原先只核对固定 owner，并在外部模型调用期间持有消息写入事务。模型等待后没有对实际 actor 和原确认对象作完整复核。合成测试复现账号停用/换部门/撤权后仍确认、非所有者及陈旧管理员进入模型、并发任务更新被行锁阻塞。

backend/app/workflow_service.py 将请求分为两个短事务：先取得 scheduler 锁，刷新任务与当前实际 actor，检查 owner 和部署门禁，保存用户消息并冻结模型输入与任务绑定；提交后调用模型，不持有数据库事务和全局锁；返回后重新加锁，刷新 actor、owner 与任务。会修改业务状态的决策必须仍对应相同日期、阶段、状态、材料引用、文件/上下文/产物、固定 Skill 及执行/模型配置，否则返回409且不执行。取消仍走当前状态和专用权限检查；只读回复与状态查询不推进旧业务决策。

用户消息独立保存，即使后续权限或绑定校验拒绝，也不会伪造助手成功回复或排队动作。模型等待期间用户可通过其他请求更新任务，新决策不会覆盖变化后的状态。

## 验证

19 个新增真实数据库用例覆盖模型前实际 actor、模型后身份/日期/阶段/上下文/文件绑定变化、正常确认日期及确认写入。首次11项中的10项在旧代码失败，其中并发任务更新在500ms锁等待限制下失败，证实原事务阻塞。修复后最终专项156项通过。模型替身内部断言调用方无事务，独立连接可获得global锁并更新；无真实模型调用或财务脚本执行。成功确认写入仅在隔离数据库排队合成动作。

静态diff与双轴审查通过；候选/受限恢复镜像的隔离PG迁移、重复迁移、无DDL角色、事务与恢复政策检查通过，213个AR Skill文件哈希保持。
