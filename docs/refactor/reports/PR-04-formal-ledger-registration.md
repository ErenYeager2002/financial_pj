# PR-04 正式辅助台账登记前的一致校验

## 行为改变

将历史读取的辅助台账包校验提取为 decode_formal_ledger_payload，登记前和后续读取复用同一规则。登记候选先验证任务目录、非符号链接、256MiB读取上限和固定指纹，再核对实际发布依据、包版本、许可文件集合、JSON记录集合、Base64及内嵌哈希，避免无效包先登记完成、到后续日期才失败。

独立规格审查还发现校验后重新复制源路径的窗口。现已在登记后比较复制产物哈希与候选固定指纹，不一致使用既有清理入口删除本次复制及记录并抛错，不写入formal_ledgers或完成状态。没有宣称文件系统具备绝对原子性；仍依赖受控输出目录与外层事务。

## 验证

48项PG相关测试通过。新增9项注册边界测试覆盖有效包、坏JSON、错误发布、缺少/多余台账、内嵌摘要、Base64、符号链接以及校验后源文件变化。发布依据使用真实隔离PG与合成文件；权限/租约用既有独立用例覆盖，此处Stub ArExecution以隔离注册边界。复制变化场景调用真实_register_artifact并核对清理后的目录及数据库。合法包用注册哨兵证明到达登记入口，不声称验证了真实财务全流程。

静态diff检查及两轴独立审查通过，审查发现的复制窗口已修复并复核。候选和恢复镜像迁移/运行/事务/回放限制验证通过，444项后端及Skill文件哈希匹配。线上结果以deployment.json与runtime-verified.json为准。
